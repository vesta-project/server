## Parallel lanes and merge boundaries

- H00 first; L01 may then start against fixtures while H01 proceeds. L02/L03/L04/L05 are sequential where they share launcher stores/navigation until launcher mapping identifies non-overlapping files.
- After H01: H02 (accounts/sessions), H05 (server composition), H14 (new browse/inspection modules) can run independently; H14 OS validation waits for H11. H03 edits transport TLS and can run beside H02/H05, but not H08's transport integration.
- H04 follows H02/H03 and owns its new authority/local-control modules. H06 owns a new worker wire module after H05; H07 follows it and owns execution checks. Do not run H05/H07 together on host/authorization composition.
- H08 then H09 then H10 serialize transport/composition integration. H11 can develop service-account modules beside H08/H09, but its final launch adapter must follow H06 and land before H10/H12 use it. H12 owns setup platform/bootstrap edits; H13 follows its listener/firewall integration.
- H14 and H15 are independent after shared module skeletons from H01: imports vs Java/resources. H16 consumes both and owns provisioning/copy adapter changes; H17 follows, never concurrent on registry/import commit logic.
- Follow-ups F01/F02 can use disjoint lookup vs invite modules; F03 must finish before F04 touches SFTP/worker ownership. F05 modes must serialize shared provisioning changes. Windows, public-network and joined-PC integration should not concurrently edit shared setup/router composition.

## Decisions and release risks

No further owner decision blocks contract work. X01 assumes primary owner has a Microsoft-backed Java profile; ask whether non-Java Microsoft accounts must own hosts before H02 ships. Obtain the actual AMP instance path/version during manual testing, not by guessing. Biggest risks: PAKE suite/exporter interoperability and unaudited dependency, Linux credentials/account separation, uncertain AMP source/process visibility, modpack launch detection, and update health still bound to a single server. Do not silently weaken those gates to claim acceptance. Public invites, full CLI parity and other wizard modes are deliberately outside X01, but their contracts are reserved now.
