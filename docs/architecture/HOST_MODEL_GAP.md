# Host model: phase 0 gap analysis

2026-11-13. Baseline: `origin/main` b6b6c0d; this branch adds the accepted plan at b99e82b. Code, rather than the plan's description of “today”, determines reuse. Documents only; proposed contracts are in `protocol/host-v1/README.md`.

## Recommended adjustment

Deliver the Linux LAN import slice by interleaving phases 1, 3, 4 and 5. Do not wait for many workers, public networking, all wizard modes, Windows services or complete CLI parity. Freeze the host/server split now, initially support one registered server, and preserve existing management behavior behind an explicit server-id adapter.

Keeping `serve` in one process is less code initially: it already composes all management services. It is safe only if Minecraft cannot read host secrets or reach privileged control. Today the supervisor trusts the same account (`crates/vesta-supervisor/src/native.rs`); moving routes alone does not provide that property. Recommend extracting one worker and separating its Linux account in the first slice, reusing its composed services and supervisor. A same-account preview could precede it locally, but is not the LAN acceptance release. Full many-worker scheduling and Windows isolation can follow. This is a larger first increment than a router wrapper, but avoids a second authorization redesign and a remotely writable mod obtaining ownership keys.

## Acceptance hazards and evidence

- AMP defaults are hints, not a fixed layout: [CubeCoders data locations](https://discourse.cubecoders.com/t/where-does-amp-store-its-data/1820) and [instance troubleshooting](https://discourse.cubecoders.com/t/diagnosing-amp-application-startup-issues/2289) identify `/home/amp/.ampdata` and its `instances` datastore. Custom datastores and unreadable parent directories are expected. Never run Vesta as root or recursively change AMP ownership to make import work.
- Account verification today proves a Microsoft-backed Minecraft Java profile through Mojang `join`/`hasJoined`; it does not verify an arbitrary Microsoft identity token. Reuse this deliberately, subject to the owner question below.
- `TlsListener`, `Transport`, worker subjects, management projections, pack URLs and update health all assume a server identity. Prefix rewriting without an explicit trusted server selection risks cross-server access and incorrectly scoped download tickets.
- Copying a running world is unsafe even if the port changes. Require the source stopped before snapshot/copy and require a second check before start. Disabling AMP auto-restart belongs in the owner instructions; do not kill arbitrary PIDs or operate AMP remotely.
- Unknown software, custom shell wrappers and unreadable process metadata must produce a resolvable blocking review, never a guessed Java command. No execution from the source during detection.

## Owner-only question

The smallest sound reuse requires the primary owner to have a Microsoft-backed Minecraft **Java** profile and online Mojang access during claim/link. Is ownership without Java entitlement required? That would require a separate, registered Microsoft OIDC application/audience contract; it must not silently accept a generic Microsoft token. The first slice assumes the existing Java account path, which matches the stated Minecraft use case.
