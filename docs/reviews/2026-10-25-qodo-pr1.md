## Fixes

1. [Restore byte counts](https://github.com/vesta-project/server/pull/1#discussion_r4369559996):
   shared streaming writer verifies each chunk hash, checked byte growth and exact declared
   file size. Both inspection and in-place restores use it; in-place validation completes
   before the temporary file replaces existing content. Tests cover omitted/all-missing
   chunks and declared sizes both larger and smaller than actual bytes, preserving the old file.
2. [Inherited-pipe descendants](https://github.com/vesta-project/server/pull/1#discussion_r4369560000):
   each generation owns a Unix process group or Windows kill-on-close job. Windows launch
   is suspended until job assignment, then resumes its pinned initial thread. Force-kill,
   guarded force-kill and owner cleanup terminate the family even while Draining. Unix
   waitid(WNOWAIT) retains the exited leader until cleanup, preventing group-ID reuse while
   a family kill remains possible. Tests exercise live and exited parents, inherited pipes,
   restart after cleanup, owner drop and retained Unix child identity.
3. [Failed inspection restore output](https://github.com/vesta-project/server/pull/1#discussion_r4369560005):
   restore into an owned private temporary directory and publish the job directory only on
   complete success. Failure drops that temporary tree, never the selected final destination.
   Tests corrupt a late chunk after earlier files have been written, check stage removal,
   successful publication and refusal to replace existing output.
