One product · distinct trust boundaries

Keep the complexity behind the installer.

The launcher is an interface. The agent and supervisor keep operations alive without it.

01 · Operator interface

Launcher

Paired-device access, capabilities, progress and notifications. UI implementation is outside this plan.

02 · Network boundary

Management agent

Identity, roles, vault, packs, durable work, backups and integrations. HTTPS with verified device authentication.

03 · Protected local IPC

Process supervisor

Launch, stdin, live output, process generations and save cleanup. No network listener.

04 · Game boundary

Minecraft

Separate OS identity. Server files and game logs stay here; plugins cannot access Vesta's protected state.

Optional connector: compatible mod/plugin for player, tick, admission and flush signals. It does not grant management roles or control-plane authority. Narrow OS helpers handle privileged setup/snapshots when needed.

Adopt, don't disrupt

Use an existing root. Preserve scripts and worlds. Take over on the next approved restart, with custom scripts/service adapters when needed.

Agent restart ≠ game restart

Minecraft continues while the agent reconnects and reconciles state. Supervisor updates wait until an approved game stop.

Client pack ≠ server code

A complete client-pack release is live immediately, or at its scheduled time. Managed JAR replacements wait for game exit.

Recovery stays deliberate

No automatic backup restoration. Owner confirmations, crash-safe journals and independent autosave cleanup protect the recovery path.

A migration, not a clean-sheet rewrite.

Keep useful codecs, APIs and tests. Change the MVP's authority, lifetime and pack boundaries where they conflict with the accepted design.

Highest-priority design gaps

  • Done in Rust: OP and permission-level authority is replaced by independent roles and capabilities. This is library level and not yet reachable by a remote device.
  • Open: loopback administration is refused, but authenticated OS-local recovery is not built.
  • Done in Rust: passwords are Argon2id verifiers in SQLite, with no plaintext secrets. A protected vault is still open.
  • Partly done: silent force kill is removed; kill is a separate confirmed action. Separating the agent's lifetime from the game is open, and no supervisor exists.
  • Done for packs: packs come from configured sources, not live scans. A trusted publish path from the running server is open.
  • Done in Rust: linked-parent and alias checks on file paths, and durable operations with recovery. Automation has not started.
